# 检查歌曲与需求输入

先读取[共享执行协议](../pv-plan/references/protocol.md)，确定工程根目录、任务目录和当前授权范围。独立调用时也检查本阶段前置产物；状态未创建则交 `$pv-plan` 初始化，不把本项目原歌数据自动当作新歌数据。

## 输入

用户请求、实际音频/歌词文件、已有成片和参考要求。

## AI 执行

运行总入口 inspect，检查音频可解码、时长/采样率/声道，读取歌词而不执行歌词 JS。核对歌词文本与歌曲版本，已有 JSON 的时间范围、递增节拍、词项顺序和包络长度。
区分复现现有作品、换歌、局部改场景、只修分析。记录音频和歌词指纹、语言、目标宽高/fps、质量/交付范围、循环要求与用户给出的参考；未指定时可提出当前工程的 1080p60 默认方案并标明假设。
缺少音频或无法确定歌曲版本是依赖阻塞；未知风格可先用用户意图起草。纯器乐、非英语、多语言、竖屏、变速曲目可进入适配流程，不能声称当前工程已支持它们。新歌的现有 JSON 不得因文件存在被当作对应新音频的数据。

## 产物与完成条件

任务目录 brief.json、intake.md：输入清单、媒体信息、有效/缺失项、范围及假设。

音频确实被探测/解码；歌词可解析；明确哪些数据匹配当前歌曲；必要缺失项已具体列出。

## 需要人提供什么

实际缺失的歌曲/歌词文件、无法由文件判断的歌曲版本或核心交付目标。不要要求用户手填 AI 能探测的音频参数。

## 交接

按共享协议把实际验证、输入指纹、产物和剩余问题写入阶段报告，再登记状态。环境审计；换歌还需项目适配。
