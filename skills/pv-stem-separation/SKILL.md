# 分离并校验声部

先读取[共享执行协议](../pv-plan/references/protocol.md)，确定工程根目录、任务目录和当前授权范围。独立调用时也检查本阶段前置产物；状态未创建则交 `$pv-plan` 初始化，不把本项目原歌数据自动当作新歌数据。

## 输入

当前混音与已验证的分离模型。

## AI 执行

按common实际路径运行Demucs；原项目示例为 uv run --frozen python -m demucs -n htdemucs_ft -o stems ../audio/pdoom.mp3。新歌应使用其真实路径/输出名。
用已记录的主唱模型分离，依据实际声部标签确定lead输出，再拷贝到common期待的lead.wav。保留分离原件，记录命令、模型、输入指纹与输出元数据。
检查每个WAV可解码、采样率/声道/时长、非静音、削波和明显串音。当前load_stem要求44100 Hz；需要重采样时保留原件并统一生成路径。听/查看代表性困难段，不能只用文件名判定质量。

## 产物与完成条件

四个Demucs声部、lead.wav、stems.md（来源/质量/时长）。

五个必需声部确实可读取且匹配当前输入；主唱/伴唱分离质量被检查。

## 需要人提供什么

若分离质量不足，可请求用户已有主唱/工程stem；先由AI尝试有依据的模型/参数调整。

## 交接

按共享协议把实际验证、输入指纹、产物和剩余问题写入阶段报告，再登记状态。pv-time-calibration。

执行本阶段时读取[相关操作参考](../pv-plan/references/models.md)；命令以当前工程代码和平台验证结果为准。
